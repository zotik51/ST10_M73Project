# ST10_M73Project

Реверс и доработка прошивки ЭБУ **Январь 7.3 (M73)** на микроконтроллере **ST10F275/F276** (ядро C166).
Исходная прошивка: кастомная `j73s_2.20.2` (20‑06‑2020), сделана на основе стоковой `I205_SP` (`21124-1411020-32`, SAMARA‑1.6L,16V).

## Содержимое

| Путь | Что это |
|---|---|
| `firmware/ST10.bin` | Исходный образ внутренней флеш‑памяти, 576 КБ (`0x000000–0x08FFFF`) |
| `firmware/ST10.map` | Исходная карта калибровок (формат `M73EdCard`, зашифрована) |
| `maps/ST10.map.dec` | Расшифрованная карта |
| `maps/calibrations.csv` | 444 параметра: адрес, тип, название, единица, раздел меню |
| `out/ST10.asm` | Полный листинг дизассемблера (~63 тыс. инструкций) |
| `out/functions.csv` | 1332 функции: как найдена, сколько вызовов, какие калибровки использует |
| `out/xrefs.csv` | Перекрёстные ссылки: калибровка → инструкция → функция |
| `tools/` | Скрипты (см. ниже) |

## Карта памяти образа

| Диапазон | Содержимое |
|---|---|
| `0x000000–0x003FFF` | Загрузчик. Таблица векторов перенаправляет на `0x4000+N` |
| `0x004000–0x00411F` | Таблица векторов приложения (`JMPS` на обработчики в сегментах 1–2). Сброс → `0x01A720` |
| `0x018000–0x02BFFF` | Код (сегменты 1–2: стартап, обработчики прерываний, библиотека) |
| `0x030000–0x04FFFF` | Код (сегменты 3–4) |
| `0x060000–0x063FFF` | Идентификация и конфигурация (страница `0x18`) |
| `0x068000–0x06FFFF` | Пусто в образе, но код читает (страницы `0x1A/0x1B`): вероятно, данные, которые пишутся во время работы |
| `0x074000–0x07BFFF` | **Калибровки, основная копия** (DPP0=`0x1D`, DPP1=`0x1E`) |
| `0x080000–0x087FFF` | Калибровки, резервная копия (идентична основной). Используется, если не сходится признак по `0x7BFFE` |
| `0x0F0000–0x0FFFFF` | XRAM, это не часть образа: переменные (страницы `0x3C/0x3D`, DPP2=`0x3C`) |

Что важно знать о коде:
- **Код сгенерирован компилятором C** (Tasking/Keil C166). Признаки: пользовательский стек на `R0` (`MOV [-R0], Rn`), стандартные прологи и эпилоги, библиотечные хелперы интерполяции (`sub_01B7EE`, `sub_01B7FA`, `sub_01BC58` …). Значит, функции можно декомпилировать обратно в C.
- **Почти всё работает в прерываниях.** Главный цикл — это `IDLE` в цикле. Обработчики переключают банк регистров через `SCXT CP` и вызывают задачи через указатели в RAM (`0xE13E–0xE150`, `0xE276` …), которые выставляются при инициализации.
- Таблицы (кривые и карты) передаются в хелперы интерполяции как константа: `MOV R12,#ofs` → `CALLS sub_01B7EE`.
- Около 4700 префиксов `EXTP`: в основном для доступа к XRAM (`0x3C/0x3D`), к конфигурации на `0x60000` (`0x18`) и к константам в коде (`0x0E`).

## Инструменты

```bash
python3 tools/decrypt_map.py firmware/ST10.map maps/ST10.map.dec
```

```bash
python3 tools/map_to_csv.py maps/ST10.map.dec maps/calibrations.csv
```

```bash
python3 tools/st10dis.py firmware/ST10.bin maps/calibrations.csv out [доп.точки входа...]
```

- **decrypt_map.py** — расшифровка `M73EdCard`. Тело файла — XOR с 10‑байтным ключом `de58a299fa8497e055aa`. Индекс ключа сбрасывается в начале каждого записанного поля, а границы полей нигде не хранятся, поэтому фаза восстанавливается проходом Витерби.
- **map_to_csv.py** — извлекает записи «название → адрес». Формат записи описан в docstring. Пока разобраны только название, тип, адрес и единица; размерности таблиц, оси и масштабы ещё не выделены.
- **st10dis.py** — дизассемблер C166/ST10 с рекурсивным обходом. Что умеет:
  - отслеживает DPP, `EXTP`/`EXTS`/`EXTR`;
  - находит обработчики, вызываемые через RAM‑указатели;
  - заполняет пробелы: код, до которого нельзя дойти по прямым переходам;
  - подписывает имена SFR и калибровок.
  
  Таблица SFR (`tools/st10_sfr.py`) неполная и составлена по памяти, её нужно сверить с даташитом ST10F275/F276.

- [ ] Разметить задачи прерываний: ДПКВ/синхронизация, впрыск, зажигание, АЦП, K‑line
- [ ] Сверить SFR и векторы с даташитом, разметить CAPCOM‑каналы
- [ ] Ассемблер или линковщик патчей: новый код в свободную флеш и перенаправление вызовов. Кандидаты по образу: `0x050400–0x05FFFF` (63 КБ), `0x028E12–0x02FFF5` (28 КБ), `0x04CD0E–0x04FFFF` (12 КБ).
  - `0x064000–0x073FFF` пустой в образе, но код читает `0x68000–0x6FFFF` (страницы `0x1A/0x1B`). Скорее всего, это эмуляция EEPROM или адаптации, туда ничего не класть.
  - `0x008000–0x017FFF` во флеш ST10F27x не отображается, тоже не использовать.
- [ ] Пересчёт контрольных сумм при прошивке

В карте нет основных стоковых таблиц (базовые ЦН, УОЗ и т. п.): они, видимо, описаны во встроенной базе редактора. В карте только параметры кастомной части и часть стоковых.
