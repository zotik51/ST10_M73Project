# Синхронизация по ДПКВ / ДФ и привязка событий к углу

Разбор по дизассемблеру `out/ST10.asm`. На железе не проверялось. Где вывод сделан по косвенным признакам, это отмечено.

## 1. Аппаратная часть

| Сигнал | Ресурс МК | Где видно |
|---|---|---|
| **ДПКВ** (60‑2) | **CC13** (P2.13), захват по таймеру **T0** | ISR `0x0197CA` через указатель `0xE14A` (вектор CC13INT `0x74`) |
| Фронт ДПКВ | `CCM3` CC13: mode 1 (нарастающий) или 2 (спадающий), выбирается битом 0 байта `0x76049` | `sub_01BF62` |
| **ДФ** (датчик фазы) | **CC7** (P2.7): прерывание на фронт сбрасывает флаг `FD14.10` | ISR `0x028A82` |
| **Катушки 1–4** | **CC0–CC3** (P2.0–P2.3), compare по T0 | ISR `0x0224C8 / 0x02252A / 0x02258C / 0x0225EE` |
| Ограничение тока катушек | CC15 (захват спадающего фронта) | ISR `0x022672`: аварийно гасит каналы CC0–3 |
| Окно детонации (HIP9011) | P6.4 + T4 (интегратор), окно в зубьях `0xE001..0xE002` | `sub_019A28` @ `0x019B7C` |
| Задачи «на цилиндр» | **CC12 как программное прерывание** (`BSET CC12IC.7`) | ISR `0x01A5C8` → `sub_019D2A` (расчёты на цилиндр), `sub_01C284` |
| Тахо‑выход (предположительно) | P3.0: установка на зубе 1, сброс на зубе 11 каждого сегмента | `0x019BB8` |

T0 работает в режиме счётчика (`T01CON = 0x4448` @ `0x01C8E6`), и, судя по настройке, тактируется переполнениями T6 (GPT2, `T6CON`, `CAPREL`). Тогда шкала времени для захвата и для compare одна и та же. Точную частоту тика нужно сверить с даташитом.

## 2. Переменные (IRAM)

| Адрес | Размер | Смысл |
|---|---|---|
| `0xE000` | byte | Состояние синхронизации: `0,1` — пропуск первых зубьев, `2` — поиск, `3` — увиден нормальный зуб, `4` — **синхронизировано** |
| `0xE004` | byte | Последний реальный зуб перед пропуском = **57** (пишется в `sub_0197AC`) |
| `0xE005` | byte | Последний виртуальный зуб = **59** |
| `0xE007` | byte | Зуб, на котором опрашивается ДФ (= 0, `sub_0197C4`) |
| `0xE00C` | word | Период текущего зуба (тики T0) |
| `0xE00E` | word | Время последнего зуба (захват CC13 или время виртуального зуба) |
| `0xE010` | word | Период предыдущего зуба. Им же генерируются виртуальные зубья |
| `0xE012` | byte | **Номер зуба 0..59** в обороте (0 — первый зуб после пропуска) |
| `0xE014` | byte | **Позиция 0..119 в цикле 720°** = `E012 + 60·(второй оборот)`. Одна единица = 6° |
| `0xE013` | byte | Зуб внутри сегмента цилиндра = `E014 mod 30` |
| `0xE026` | byte | Номер сегмента (цилиндра) = `E014 / 30`, 0..3 |
| `0xE022/E023` | byte | Зуб и сегмент события впрыска (из фазы впрыска, `sub_022798`, `sub_0227DE`) |
| `0xE027` | byte | Цилиндр для расчёта впрыска = `(E026 − E023) mod 4` |
| `0xE029` | byte | Цилиндр для задач на зубе 8 сегмента = `(E026 − 1) mod 4` |
| `0xE001/E002` | byte | Окно детонации: начальный и конечный зуб в сегменте |
| `0xE29E` | 4×4 | Расписание катушек на 4 цилиндра: `{зуб_начала_накопления, доля, зуб_искры, доля}` |
| `0xE3D4` | byte | Счётчик ошибок синхронизации |
| `FD0A.11` | bit | Идёт генерация виртуальных зубьев (CC13 в режиме compare) |
| `FD0A.14` | bit | Половина цикла (0–360° / 360–720°) |
| `FD08.10` | bit | Ошибка синхронизации |
| `FD06.4` | bit | Ошибка фазы (ДФ не совпал с ожидаемым) |

## 3. Алгоритм ISR ДПКВ (`0x0197CA`)

```
period = capture - last_capture

state 0/1: пропуск зубьев после старта (state++)
state 2/3: поиск пропуска
    r = period / prev_period
    r ∈ [0.5 .. 1.5]  → нормальный зуб, state = 3   (при prev > 0xFF нижняя граница не проверяется)
    r ∈ [2.5 .. 3.5]  (до 4.0 на малых оборотах, prev > 0xFF)
        и state == 3  → пропуск найден: state = 4, tooth = 0
    иначе             → state = 2
state 4 (синхронизировано):
    допуск: period ∈ [prev/2 .. 2·prev] (на высоких оборотах ≤ 1.5·prev)
    вне допуска → ошибка: state = 0, все катушки гасятся (CCM0 = 0, P2.0–3 = 1), E3D4++
    tooth++
    tooth == 57 → CC13 переводится в compare: виртуальные зубья 58, 59
                  ставятся через prev_period, без захвата реальных фронтов
    tooth == 59 → CC13 обратно в захват
    tooth == 60 → tooth = 0 (первый реальный зуб после пропуска)
    tooth >  60 → ошибка синхронизации
```

Пропуск не измеряется как длинный период. Вместо него ISR **сама генерирует два недостающих зуба** через compare. Поэтому остальной код видит равномерную сетку из 60 зубьев по 6°, а проверка допуска на зубе 60 заодно подтверждает, что пропуск на месте.

**Фаза (ДФ):** на зубе `E007 = 0` уровень P2.7 и флаг фронта ДФ (`FD14.10`) сравниваются с ожидаемыми.
- Если совпало, по ним выставляется `FD0A.14` (половина цикла). Инверсию задаёт бит 2 байта `0x76046`.
- Если не совпало, ставится `FD06.4` (ошибка фазы).
- Без ДФ `FD0A.14` просто переключается каждый оборот: попарно‑параллельный режим.

**После каждого зуба** (`sub_019A28`):
- считаются `E014`, `E013`, `E026`;
- на зубе `E022` сегмента ставится программное прерывание CC12, оно рассчитывает впрыск для цилиндра `E027`;
- на зубе 0 или 30 измеряется время полуоборота (буфер `0xE096..0xE0A4`), отсюда обороты;
- на зубе 5 расписание катушек копируется в рабочий буфер `0xE29E`;
- на зубе 8 запускаются задачи на цилиндр;
- на зубьях `E001` и `E002` открывается и закрывается окно детонации;
- в `E29E` ищется событие катушки с позицией `E014`. Если нашлось, `CCx = время_зуба + доля·2·период/256`. Какие катушки срабатывают, задаёт маска из конфигурации `0x60730` (`+8` в попарном режиме).

## 4. Что зашито константами

Для другого диска и другого числа цилиндров придётся менять вот это:

| Адрес | Константа | Смысл |
|---|---|---|
| `0x0197AC` | `57`, `59` | Последний реальный и последний виртуальный зуб (60‑2) |
| `0x019840` | `SHL #1` (×2), допуски ×0.5/×1.5/×3 | Распознавание пропуска ровно из **2** зубьев |
| `0x019982` | `60` | Зубьев на оборот |
| `0x0199FC` | `+60` | Второй оборот → позиция 60..119 |
| `0x019A08` | `/30` | Зубьев на сегмент цилиндра = 120 / **4** |
| `0x019A84`, `0x019B32`, `0x019B70` | `4` | Число цилиндров (перенос по модулю) |
| `0x019A9C` | `30` | Точки измерения полуоборота (зуб 0 и 30) |
| `0x019AF4` | `4` | Счётчик сегментов |
| `0x019B12`, `0x019B64`, `0x019BB0`, `0x019BBC`, `0x019BC8` | `5`, `8`, `6`, `11`, `1` | Зубья внутри сегмента для служебных задач |
| `0x019BFA` | `CMPI1 R3,#3` | Цикл по **4** записям расписания катушек |
| `0x019C08…0x019D26` | CC0–CC3, P2.0–P2.3 | 4 канала катушек |
| `0x0227A8…0x0227CA`, `0x0227F4…0x022854` | `120`, `+19`, `/30`, `60`, `/6` | Фаза впрыска: 120 позиций, **ВМТ = зуб 19**, сегмент 30 |
| `0x01A956`, `0x01A9EE…0x01AA20` | `120`, `30`, `+19` | Окно детонации: перевод из градусов в зубья |
| `0x0224A0` | `+120` | Перенос позиции по модулю 720° |
| `0x01CB12` | `CC0..CC3 = 0x6E, 0x33E, 0x15E, 0x24E` | Начальные значения compare катушек |

Скорее всего, это не полный список: шаг 6° (одна позиция = зуб 60‑2) неявно заложен везде, где угол переводится из градусов в зубья. Это все функции, читающие `E013`, `E014`, `E022…E029` и таблицы фаз. Их нужно проверить по `out/xrefs.csv`.

## 5. Как добавить другие диски и другое число цилиндров

**Рекомендуемый путь: «виртуальная сетка 60‑2».**

Остальная прошивка уже работает не с реальными зубьями, а с равномерной сеткой: 120 позиций по 6° на цикл, время зуба `E00E`, период `E010`. Прошивка и сама досоздаёт виртуальные зубья в пропуске. Поэтому:

1. Пишем новый ISR ДПКВ вместо `0x0197CA`, параметризованный калибровками:
   - число зубьев, число пропущенных, смещение ВМТ, фронт;
   - тип ДФ: уровень на зубе или отдельный фронт, многозубый диск распредвала.
2. ISR распознаёт реальный диск (36‑1, 60‑2 с другим смещением, 24‑1, 4+1 и т. п.) и **генерирует ту же сетку 6°** через compare CC13. Это тот же механизм, что уже используется для двух пропущенных зубьев, только виртуальные зубья вставляются и между реальными.
3. Наружу ISR выставляет те же `E00E`, `E010`, `E012`, `E014`, `FD0A.14`, `FD0A.11`, `FD08.10` и вызывает `sub_019A28` как раньше.

Тогда остальной код (впрыск, УОЗ, детонация, обороты) не меняется. Цена: точность угла ограничена интерполяцией между реальными зубьями. На дисках с редкими зубьями при резком ускорении появится ошибка. Это можно компенсировать прогнозом по ускорению.

**Число цилиндров** так просто не решается. Сегмент 30 позиций = 4 цилиндра зашит в делениях `/30`, в переносах по модулю 4, в 4‑х записях `E29E` и в 4 каналах CC0–CC3.
- **3 цилиндра:** сегмент 40, 3 канала. Это укладывается в существующие ресурсы, но нужно патчить все места из таблицы выше.
- **6 и 8 цилиндров:** не хватает каналов compare для катушек и форсунок. Нужно смотреть, какие ещё выходы CAPCOM разведены на плате. Ресурсов CC16–CC31 у МК достаточно, вопрос в силовых драйверах.

Перед изменениями нужно:
1. Найти выходы форсунок: вероятно, CC16–CC21 или CC8–CC11 (обработчики через указатели `0xE13E–0xE144` и `0xE276–0xE27C`).
2. Разобрать расчёт угла в `sub_0227DE`, `sub_022798` и в расчёте УОЗ, то есть откуда берутся `E29E` и доли.
3. Свести все места, где угол переводится из градусов в зубья.
